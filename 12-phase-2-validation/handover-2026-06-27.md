## What was done this session

### 1. UJ2 debugging — root cause identified

Attempted to debug why FA09A_Filter_CandidatesByTitle was returning `{ "body": [] }` despite calendar events being present.

**Investigation steps:**
- Confirmed calendar data was correct — all 10 events including both Ace meetings present in FA09 RAW output
- FA09A "From" field went through three expression attempts:
  1. `outputs('FA09_RAW_CandidateArray_DoNotUseDownstream')` — returned `[]` (original)
  2. `outputs('FA09_RAW_CandidateArray_DoNotUseDownstream')?['body/value']` — InvalidTemplate error
  3. `body('FA09_RAW_CandidateArray_DoNotUseDownstream')?['value']` — Null error
  4. Back to `outputs('FA09_RAW_CandidateArray_DoNotUseDownstream')` — filter ran but still returned `[]`

**Root cause confirmed via FA03A DEBUG RawInputs:**
All trigger parameters (`UserSearchText`, `InSelectedNumber`, `OriginalUserSearchText`, `DateContext`) were arriving as empty strings. The search text was never being received by the flow.

**Underlying architectural reason:**
Copilot Studio agent flows receive parameters as named trigger fields (`triggerBody()?['UserSearchText']` etc), not via `triggerBody()?['text']`. FA09A's filter expression was built around `triggerBody()?['text']` which is a Teams messaging field — never populated in agent flow calls. This is a fundamental mismatch in the original design.

### 2. Teams consent loop issue

During testing, a "Connect to continue" consent card appeared in Teams for Office 365 Outlook. Every time Allow was clicked, it triggered a new flow run before auth was established, causing BadGateway errors in a loop. This is a known pattern — every Flow A publish invalidates the Teams end-user consent token.

**Workaround confirmed:** Use the Copilot Studio test panel instead of Teams for post-publish testing.

### 3. Topic flow references broken by relinking

When attempting to fix "Flow not found" errors in the Topic, relinking the flows reset all input mappings to blank. C2_Call_FlowA_Initial inputs were manually remapped:
- UserSearchText = Topic.MeetingName
- MeetingName = Topic.MeetingName
- InSelectedNumber = ""
- OriginalUserSearchText = Activity.Text
- DateContext = "today"
- MaxCandidates = 5

Topic checker reached 0 errors after remapping.

### 4. Connection refresh order established

When refreshing connections in Copilot Studio Settings → Connection Settings, refreshing one flow can make another go Stale. Confirmed safe order:
1. PA - Find Outlook Meeting Details for OneNote first
2. PA - Resolve OneNote Meeting Section second
3. **PA - Resolve Meeting Selection last** (this is the one being tested — must be refreshed last)

### 5. UX redesign decision

After establishing the root cause, the decision was made to redesign the UX rather than patch the search approach. The new design:
- Eliminates the need for users to type meeting names
- Shows a numbered list of today's meetings with start times
- Allows navigation with P (previous day), N (next day), or a typed date
- User selects by number → Flow B creates OneNote page

Full spec in `design-v5-ux-rebuild-2026-06-27.md`.
