## Confirmed findings this session

### 1. AMEND-2026-07-27-001 — empty-string SetVariable + mislabeled varPageAction (Flow B, `Condition Should Create Page` False branch)
- `Set_varPageAction_ExistsNoCreate`: `""` → `"Updated"`
- `Set_varOutputPageSelfUrl_Existing`: `""` → `variables('varFinalExistingPageSelfUrl')`
- `Set_varPageAction_UpdatedAppend`: `"Created"` → `"Updated"` (was mislabeling an update as a creation)
- **Status: Retested, closed.**

### 2. AMEND-2026-07-27-002 — `Condition Is Genuine Existing Page` structurally unreachable
- Root cause: `Set varOneNoteResolverResult ExistingMapping` and `Set_varOneNoteResolverResult_Exists_OneOff` both had no `value` key at all — a new bug pattern (distinct from empty-string), now added to `living-audit.md`'s pattern reference as pattern (6).
- Fix: both now set real values (`"ExistingMapping"`, `"ExistingSection"`); condition expression updated to `contains(createArray('ExistingMapping', 'ExistingSection'), variables('varOneNoteResolverResult'))`.
- **Real-world impact confirmed live**: recapturing an already-captured meeting was silently creating duplicate OneNote pages, with the agent reporting normal success each time. This has likely been happening since this branch was first built — any historical OneNote content from repeated captures may contain undetected duplicates from before this fix.
- **Status: Retested live, closed.** Confirmed via full run trace (condition evaluates True, correct branch executes) and directly in OneNote (page count did not increase on recapture).
