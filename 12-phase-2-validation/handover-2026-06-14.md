### Fixes applied this session

1. **New action `FA09A_Filter_CandidatesByTitle`** (Filter array), inserted between
   `FA09_Compose_CandidateArray` and `FA10_Initialize_varCandidates`:
   - From: `outputs('FA09_Compose_CandidateArray')`
   - Filter query: `contains(toLower(item()?['subject']), toLower(if(empty(triggerBody()?['text']), coalesce(triggerBody()?['text_2'], ''), triggerBody()?['text'])))`
   - Filters the raw daily candidate array down to only events whose subject
     contains the user's requested meeting title (case-insensitive), with a
     fallback to `text_2` (OriginalUserSearchText) if `text` is empty.

2. **`FA13_Compose_MatchCount`** updated to `length(body('FA09A_Filter_CandidatesByTitle'))`
   instead of counting the raw unfiltered array. Now correctly returns `1` for a
   single-title match (previously always returned the total daily event count,
   e.g. 6 or 7).

3. **`FA27_Condition_MatchCount` and its full subtree** (FA27A–FA27H, FA28–FA32,
   FA33A/FA34A, FA35–FA43B) repositioned to run immediately after FA13 (previously
   nested inside `FA17_Condition_IsSelectionMode`'s False branch with a broken
   `runAfter` pointing at `FA15_Compose_IsSelectionMode`). FA27's `runAfter` now
   correctly targets `FA34_Initialize_varCandidateIndex` (itself running after
   FA13), which resolved the `ActionBranchingConditionNotSatisfied` skip that was
   blocking the entire FA27 subtree.

4. **`FA33_Initialize_varCandidateListText`** (String) and
   **`FA34_Initialize_varCandidateIndex`** (Integer) repositioned to run *before*
   FA27 (previously positioned after FA27, between FA15 and FA17) — required so
   that `FA33A_Set_varCandidateListText_Empty` and `FA34A_Set_varCandidateIndex_One`
   (inside FA27A's multi-match False branch) have these variables in scope.
   `FA33A`/`FA34A` Name fields filled in: `varCandidateListText` = `''`,
   `varCandidateIndex` = `1`.

5. **`FA02_Init_varInSelectedNumber`** — root cause of a second, previously-hidden
   bug. Its value was hardcoded/frozen as the literal two-character string `"\"\""`
   (quote-quote), not a true empty string. Because `not(empty(trim('""')))` evaluates
   to `true`, `FA15_Compose_IsSelectionMode` was *always* returning `true`, causing
   `FA17_Condition_IsSelectionMode` to always route into the selection-mode True
   branch — which calls `FA19_Compose_SelectedEvent` /
   `FA20_Compose_OutMeetingTitle`, hardcoded to index `[0]` of the unfiltered
   candidate array (i.e. always "ABC Meeting"). This was the actual mechanism by
   which the original bug manifested even after FA09A/FA13/FA27 were fixed.

   Fixed value expression:
   ```
   if(equals(triggerBody()?['text_1'], '""'), '', coalesce(triggerBody()?['text_1'], ''))
   ```
   Confirmed `FA15_Compose_IsSelectionMode` now outputs `false` for non-selection
   calls, correctly routing to FA17's False branch (the FA27 tree).
