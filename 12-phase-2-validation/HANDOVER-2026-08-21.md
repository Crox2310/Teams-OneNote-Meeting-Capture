## Working method established on this project (important — follow this)

- **Evidence-first, always.** Never propose a fix without first seeing real data (Peek Code, Activity trace raw inputs/outputs, live diagnostic tests). This project has been burned multiple times by reasoning from assumption instead of evidence — see the #3 date-guard investigation for a good example of the *right* way to do this (built two throwaway diagnostic Topics, ran them, read real results, only then wrote the fix).
- **Diagnostics before live changes.** For risky/uncertain logic (e.g. Power Fx or WDL expression behaviour you're not 100% sure of), build a throwaway diagnostic (a temporary Topic or a temporary Compose action) that tests the *exact* expression against real inputs, before wiring it into the live flow.
- **Container-level Peek Code** is much faster than action-by-action — selecting Peek Code on a top-level `Condition` captures every nested action inside it in one paste.
- **`push_files` works reliably; `create_or_update_file` has been unreliable this project** — use `push_files` for all GitHub writes.
- **Diff-verify every YAML change** before handing it to David — confirm exactly one intended change landed, nothing else drifted.
- **David builds via UI/paste-in, not you directly** — you don't have direct access to Copilot Studio or Power Automate. You give him exact expressions/values/YAML files, he pastes/clicks, then pastes back Peek Code or screenshots to confirm.

## Critical, ongoing problem: platform-level corruption

There is a **recurring, unresolved Microsoft platform bug**: `SetVariable`/Compose actions in Flow B periodically lose their `value` field entirely, usually ~26 actions at once (sometimes just one). This has now happened **9+ times** across the project's history, including twice in one afternoon during today's session, on the exact same action (`OF05c — Set varFinalMatchCount (OneOff)`).

- **Symptom**: Flow Checker shows blank-value errors, OR (confusingly) a run fails with a garbled error like `"The template function 'tring' is not defined"` — this is what a missing `value` field looks like when the action is `@string(...)` and the whole value got wiped; the platform's error reporting doesn't clearly say "value is missing."
- **New pattern observed 21 Aug**: corruption seems to correlate with **structural canvas edits** (adding/moving/repositioning actions), not just publish/save events as previously understood.
- **Fix**: restore from `known-good-values-master-reference.md`. It has every action's correct expression, organized by branch, ready to paste back. This has saved enormous time twice already.
- **A Microsoft support ticket is drafted** (`MICROSOFT-SUPPORT-TICKET-DRAFT-2026-08-15.md`) but **still not submitted** — this should now be treated as genuinely urgent given the frequency.
- **If corruption strikes while you're working**: don't panic, don't guess — pull up the reference doc, restore exactly, re-run Flow Checker, confirm 0 errors, save (don't necessarily publish immediately — see below).

## The three issues (field observations from David, 20 Aug)

**#2 — Recapture discards new content.** ✅ **DONE.** `Compose_UpdateHtmlFragment` was a hardcoded static string that never included the fresh `text_3` content — organiser updates were silently discarded on recapture. Fixed to `concat(notice, triggerBody()?['text_3'])`. Confirmed live via a real recapture test (original content preserved, new content genuinely appended, no duplicate pages). See `fix-2026-08-21-2-appendcontent-resolved.md`.

**#3 — Date entry format sensitivity.** ✅ **DONE.** Root cause: the Topic's `C6C_Check_Date` condition required `DateValue()` to succeed, but `DateValue()` can't parse `dd/MM/yy` slash format in this locale — combined with no `else` branch on the parent condition group, unrecognised input leaked straight through to Flow A and crashed on an unguarded `int()`. Fixed with a slash-aware date parser (handles both `20 Aug` and `20/08/26`/`20/08/2026`, including 2-digit-year normalisation to avoid Power Fx's `Date()` "1926 not 2026" trap) plus an `else` re-prompt branch. **A regression was caught and fixed same-day**: the new `else` branch initially broke plain number selection (e.g. typing "5" to pick meeting #5) by intercepting the fall-through that number selection relied on — fixed by adding an explicit `C6D_Check_Number` condition. Confirmed live. See `fix-2026-08-20-3-datehandling-resolved.md`.

**#1 — Per-occurrence recurring pages.** 🔶 **IN PROGRESS.** David wants each occurrence of a recurring meeting to get its own dated OneNote page (e.g. "121 Simon / David - 20 Aug 2026"), rather than the current behaviour of one page per series that gets appended to forever. Same-date recaptures should still append/protect (organiser may update details).

### #1 — what's NOT started: Ref FB-04 (the last piece)

This must be replaced with genuine date-based matching before per-occurrence pages can safely go live (otherwise, once a section has multiple dated pages, the workaround will silently pick the wrong one).

**Plan** (reasoned through, not yet built or tested):
1. There's an existing, currently-**dead** action called `Filter_Pages_By_Title` sitting in the flow (its output isn't wired to anything). Reuse it: change its filter to match pages whose title contains the occurrence date:
   ```
   @contains(item()?['title'], formatDateTime(triggerBody()?['text_5'], 'd MMM yyyy'))
   ```
2. Point `Compose_RealExistingPageId` at `Filter_Pages_By_Title`'s output instead of the raw unfiltered page list:
   ```
   @if(greater(length(body('Filter_Pages_By_Title')), 0), first(body('Filter_Pages_By_Title'))?['id'], '')
   ```
