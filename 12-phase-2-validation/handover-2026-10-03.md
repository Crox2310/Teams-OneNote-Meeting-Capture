## Fixes applied this session

### 1. Flow A — FA02 and FA04 missing value bindings (ROOT CAUSE OF DATE BUG)

**Problem:** FA02 (varInSelectedNumber) and FA04 (varDateContext) were initialised with no `value` field — both silently null. Trigger inputs `text_1` and `text_3` were discarded on every run. FA06/FA07 fell back to `utcNow()`, querying today's date regardless of what was passed in. Worked invisibly until today (Saturday) because previously the passed date and today always agreed.

**Fix:**
- FA02 value: `@coalesce(triggerBody()?['text_1'], '')`
- FA04 value: `@coalesce(triggerBody()?['text_3'], '')`

**Confirmed:** FA06 = `2026-10-02T00:00:00Z`, FA07 = `2026-10-02T23:59:59Z`. 10 meetings returned end-to-end from Teams.

### 3. Topic — C5 resolve guard condition tightened

**Problem:** After pressing P/N/date to navigate, Flow A returned `Status=OK` and a populated `MeetingTitle`. The C5 guard fired immediately, skipping the list display and jumping to capture.

**Fix:** Added `&& Topic.SelectedNumber <> "NONE"` to the guard condition.

```
=Topic.Status = "OK" && Topic.MeetingTitle <> "" && Topic.SelectedNumber <> "NONE"
```

`Topic.SelectedNumber` is set to `"NONE"` at C0B and only changed to a real number at C6G (numeric selection). Navigation paths (P/N/date) never touch it.

**File:** `topic/meeting-capture-topic-2026-10-03.yaml` (saved in outputs)

### 4. Flow A — FA36b three-tier status labels

**Updated expression** in `FA36b_Compose_StatusLabel`:

Priority order: AI Notes > Chat Captured > Captured > (blank)

- `RecapCaptured = true` → ` - **AI Notes**`
- `ChatCaptured = true` → ` - **Chat Captured**`
- Row exists, neither true → ` - **Captured**`
- No mapping row → blank

**Key finding:** SharePoint returns `ChatCaptured` and `RecapCaptured` as booleans (`true`/`false`), not strings. Expression uses `equals(coalesce(..., false), true)` not string comparison. `RecapCaptured` field absent from rows where never set — coalesce to `false` handles null safely.
